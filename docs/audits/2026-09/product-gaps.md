# Nixploy product-gap audit — what to build next

Snapshot 2026-09-11, branch `work/stability-and-landing`. Scope: feature gaps and half-built
features versus Dokploy / Coolify / CapRover / Railway expectations. Every claim below was
checked in code (paths relative to repo root; `S` = packages/server/src, `W` = apps/web/src,
`C` = apps/cli/src). Bugs fixed by the stability sweep (docs/status.md) are not repeated.

Method: 42 routers / 269 procedures cross-checked against `W` (`trpc.<router>.<proc>`), `C`
(`"<router>.<proc>"`) and `S/modules/mcp/tools.ts` (`caller.<router>.<proc>`). Result: web uses
226/269, CLI 29/269, MCP 14/269.

## 1. Present and solid

- Deploy engine: 6 builders (`S/modules/deployment/builders/index.ts:28-43`), BuildKit local cache (`builders/cache.ts`), Dockerfile path/context/`--target`/`--build-arg` (`dockerfile-builder.ts:21-48`), build path, watch paths matching, drop-zip, docker-image source with registry-scoped pull auth (`sources.ts:378-398`), per-server FIFO queue with cancel/kill (`deployment/queue.ts`), boot recovery, status reconciler + failure watchdog, rollback pins (5 kept, `deployment/rollback.ts:10`), deploy notifications, Copilot auto-explain → apply env patch → redeploy.
- Swarm runtime: replicas, CPU/mem limits+reservations, command, healthcheck form, placement (+`node.id` pin), start-first rolling update default (`deployment/swarm.ts:220-268`), ports tcp/udp ingress/host, bind/volume/file mounts (also on databases), private per-compose networks.
- Networking: domains with path + port + LE/custom/none certs (`S/modules/traefik/config-writer.ts`), global HTTP→HTTPS (`traefik/setup.ts:47-57`), redirectRegex, basicAuth, `internalPath` strip/add prefix, custom certificates, `*.traefik.me` free domains, host-uniqueness across orgs, uptime probe toggle per domain (`W/components/services/domain-manager.tsx:89-94`).
- Services: application, compose (`docker compose` or `stack`, rendered + safety-checked, isolated names, generated by AI), 5 database engines with external port, connection URL, reload, env, terminal, logs, metrics; 86 fixed templates in 15 categories; previews with PR lifecycle, fork approval gate, PR comments, expiry, auto-delete on close.
- Env: org→project→environment→service inheritance (`S/modules/projects/env-resolution.ts`), resolved-preview UI at project level, redaction for members without `secrets.read`, build args per app.
- Ops: S3 DB + volume backups with cron + `keepLatestCount` + restore picker + instance self-backup; schedules (cron shell in container/server/host) with run logs mirrored to deployment rows; 11 notification providers; alert rules (cpu/mem/restarts/deploy streak); incidents; uptime probes; 48 h metrics JSONL + fleet overview; audit log with facets; Docker control center (containers/images/networks/volumes/swarm/system) with prune guards.
- Team/auth: better-auth orgs, invitations with expiry, role ladder + per-member capability overrides (`S/modules/projects/capabilities.ts`), org-enforced 2FA, sessions card, API keys (name + expiry, per-key rate limit), org switcher + create org, quotas, branding.
- Platform: remote servers over SSH joining the primary swarm, capacity stats, drain via control center, in-app updater with rollback-on-failure, GitHub App manifest flow + GitLab/Bitbucket/Gitea PATs, GitOps (`nixploy.yaml` export/plan/apply/sync-from-URL incl. databases), MCP (13 tools), REST/OpenAPI + Swagger, CLI (13 command groups), docs/ (20 guides) + landing docs.

## 3. Half-built (server ⇄ UI/CLI/MCP mismatches)

Server-only (procedure exists, nothing calls it):

- `application.duplicate` / `application.move`, `compose.duplicate` / `compose.move`, database `duplicate` / `move` (`S/modules/databases/router.ts:335-392`) — no "Duplicate" / "Move to environment" actions in any settings tab or danger zone (`W/components/services/danger-zone.tsx`, `database-detail.tsx:201`).
- `github.update`, `gitlab.update`, `bitbucket.update`, `gitea.update` — git providers cannot be edited in `W/components/settings/git-providers/*` (delete + recreate only); `bitbucket/gitea.revealWebhookSecret` also unused, so the webhook secret is shown once at creation only.
- `gitops.syncFromGit` — neither `W/components/projects/gitops-card.tsx` nor `C/commands/gitops.ts` call it (only `syncFromUrl`).
- `monitoring.serverHistory` — server metrics are sampled to `metrics/server-<id>.jsonl` (`history.ts:623`) but no server history chart exists (`servers-view.tsx` uses `getStatsBatch` only).
- `monitoring.containerStats`, `monitoring.dockerCleanup`, `application.killBuild`, `application.readDeployments`, `application.saveDockerProvider` — superseded by other procedures; candidates for removal from the public API surface.
- `tag.update` — tags cannot be renamed/recoloured (`W/components/projects/manage-tags-dialog.tsx` has create/delete only).
- `observability.ingestLog` — public ingest endpoint with no client or docs.

Schema/engine feature with no UI:

- `applications.watchPaths` — matched by the webhook handler (`webhook-handler.ts:534-569`) but no field in `W/components/application/source-config.tsx` (grep 0). Operators cannot set it without the API.
- `domains.internalPath` — rendered by the Traefik writer (`config-writer.ts:249-263`) but the domain form has no field (`domain-manager.tsx:107-112`).
- `updateConfigSwarm`, `rollbackConfigSwarm`, `restartPolicySwarm`, `modeSwarm` (global services), `labelsSwarm`, `networkSwarm` — accepted by `application.update` (`routers/application.ts:69-84`) as untyped JSON, no forms (only healthcheck, placement, resources have UI). Zero-downtime tuning (parallelism, delay, failure action, monitor) is therefore API-only.
- Generic deploy webhook `POST /api/webhooks/deploy/<appName>` — implemented and org-scoped but the URL/instructions are not shown anywhere in the app (grep `webhooks/deploy` in `W/` = 0).
- Notification toggles `nixployRestart` and `dockerCleanup` are offered in `W/components/settings/notifications/notification-dialog.tsx:169-170` but no code ever emits those events (only `appDeploy`, `appBuildError`, `databaseBackup`, `serverThreshold`, `serviceAlert`, `uptimeFlip` are dispatched).
- `deployment/queue.ts:55` `queueDepth` is exported (`modules/deployment/index.ts:14`) but no router/UI shows queue depth or a "queued" state (ties to the known `queued` enum debt).
- `registry.imagePrefix` (push namespace) is stored and edited but only consulted for pull-auth host matching (`sources.ts:385-398`); no push path.
- better-auth `admin` plugin is enabled server-side with no admin UI (see Gaps).

UI/CLI expecting more than the server offers:

- `env` CLI command only touches `<router>.one/saveEnvironment` of a service; project/environment env procedures exist but have no CLI (`C/commands/env.ts:59-80`).
- MCP `get_service_metrics` works for local-host services only (`monitoring.replicaStats`), documented in docs/mcp.md:95 — remote-server services return nothing.

## 4. Top 10 recommendations (priority order)

1. **Deployment provenance + queue hygiene** — commit SHA/message/author/trigger on deployment rows, supersede pending jobs for the same app, real `queued` status and queue-depth badge. Cheapest win on the most-used screen. (Gaps: Deploy rows 1-2, half-built `queueDepth`.)
2. **Traefik middleware layer for every domain type** — basic-auth/redirects on compose, plus rate-limit, IP allow-list, headers, compression, forwardAuth, sticky; typed rows rendered by the single writer. Unblocks "put Authentik in front", "block a scraper", "HSTS" requests. (Networking rows 1-2.)
3. **Shared variables** — finish org-level env (writer + card), separate build-only args from runtime env, `.env` import/export. (Env rows 1-3.)
4. **Backup run history + local destination + restore verification** — a `backup_run` table with status surfaced in the backups tab and notifications; local disk destination. Backups nobody can see the status of are not trusted. (Databases rows 1-3.)
5. **Scoped API keys / service accounts + password reset + SSO** — org-bound keys with read-only/deploy scopes (CI, CLI, MCP need them), better-auth reset-password over the email provider, `genericOAuth` for teams. (Team/auth rows 1-3.)
6. **CLI parity generated from an allow-list** — lifecycle (stop/start/delete), databases, domains add/remove, env at all scopes, backups, servers add/setup, container logs; extend MCP with the same read tools. Today 29/269 and 13 tools. (Platform rows 1-2.)
7. **Remote-server builders + optional registry push** — `setupServer` installs nixpacks/railpack (or use the BuildKit container path), `pushRegistryId` per app using `registry.imagePrefix`; makes multi-node replicas and node moves real. (Deploy rows 3-4.)
8. **Wildcard/DNS-01 + per-domain HTTPS opt-out** — DNS provider credentials in platform settings, `*.example.com` domains for previews, move the HTTPS redirect from the entrypoint to per-router. (Networking rows 3-4.)
9. **Surface the half-built server features** — duplicate/move actions, watch paths and `internalPath` fields, update/rollback/restart-policy forms, git provider edit, tag edit, server metrics history chart, deploy-hook URL card, `syncFromGit`, emit or drop the two dead notification toggles. All S-effort, mostly UI. (Section 3.)
10. **Pre/post-deploy hooks and preview knobs** — migration hook before rollout, preview-only env + cap + default TTL, then incidents ack/resolve and a public status page as the observability follow-up. (Deploy row 5, Previews, Observability rows 2-4.)
