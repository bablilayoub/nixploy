# Nixploy security posture audit — 2026-09-10

Branch `work/stability-and-landing` (post stability sweep). Read-only review; findings from the sweep
(`docs/status.md` "What the stability sweep did") are not repeated. Every claim carries file:line
evidence; **V** = verified by reading the full code path, **P** = plausible (inferred, not traced).

## 1. Threat model

| Attacker | Position | Primary goals | Main surfaces |
| --- | --- | --- | --- |
| Anonymous internet | Reaches Traefik :80/:443 (and :3000 if `NIXPLOY_PORT` was opted in) | Credential guessing, first-admin race, DoS, webhook abuse | `/api/auth/*`, `/setup`, `/api/webhooks/*`, `/api/trpc` body size, TLS/ACME |
| Tenant member (viewer→deployer) | Valid session/API key in one org | Read other tenants' data, escalate within org, reach host | tRPC/REST/MCP procedures, WS streams, notification/probe URLs (SSRF) |
| Org admin/owner | `servers.manage`, `docker.manage`, `members.manage` | Reach the **cluster** (other orgs), host root, panel secrets | `server.*` (Swarm join), `docker.*` on own node, compose/mounts, capability overlays |
| Compromised app container | Root inside a tenant task on `nixploy-network` (if it has a domain) or `<app>-net` | Lateral movement to panel, Postgres, other tenants, docker socket | Overlay DNS (`nixploy:3000`, `nixploy-postgres:5432`), volume/bind mounts, kernel caps |
| Malicious template / compose | Compose YAML deployed via `template.deploy` / `compose.*` | Host escape via mounts/privileged/labels | `compose-file.ts` safety checks, `hostPrivileged` gate |
| Instance admin | `user.role=admin` (first signup) | Trusted root. Impersonation, updates, host mounts — by design | better-auth `admin()` plugin, `assertInstanceAdmin` |

Design facts that frame everything below: one Node process runs as **root** with the docker socket
(`docker/Dockerfile:69`, `install.sh:782`); Postgres and the panel share the tenant-facing overlay
(`install.sh:669-670`, `:769`); there is no CSP/HSTS anywhere; API keys have no scopes.

## 2. Findings

Severity: critical / high / med / low / hardening. Effort: S (<1 day) / M (days) / L (design change).

### 2.3 Authorization (sample of 60+ procedures; see agent table summarised)

Per-procedure discipline is strong: every mutation read carries `assertCapability`/`assertOrgRole`/`assertInstanceAdmin`, every id-taking procedure resolves the org first; MCP tools and the REST adapter both go through `appRouter.createCaller(ctx)` with the same `protectedProcedure` middleware, so capability checks and the org 2FA gate apply identically (`modules/mcp/server.ts:29`, `api/[...rest]/route.ts:96`, `trpc/init.ts:38-74`). `publicProcedure` is used only in `routers/setup.ts`. Self-escalation via roles/overlays is structurally blocked (`modules/auth/org-rank.ts:8-47`, `routers/organization.ts:349-389`). The findings are about **blast radius**, not missing asserts.

### 2.4 Secrets at rest and in flight

`lib/encryption.ts` is sound AEAD (AES-256-GCM, 12-byte random IV, tag verified, `v1:` prefix). Read-side redaction is thorough: registry passwords, SSH private keys, git-provider tokens, TLS keys, S3 secret keys, AI key and basic-auth hashes are **write-only** at the router boundary (`routers/registry.ts:56-58`, `ssh-key.ts:28-30`, `github.ts:50-63`, `certificate.ts:88-96`, `destination.ts:97-109`, `ai/settings.ts:168`, `security.ts:19-21`); env/compose/DB passwords are nulled for callers without `secrets.read` (`trpc/redact-secrets.ts`). Exec errors are reduced to the command's first word (`utils/exec.ts:62-70`) and deployment logs pass every merged env value through `redact()` (`deployment/logger.ts:66-88`, `worker.ts:171-263`). Audit metadata carries only ids/roles/flags. `env -i` + allowlist keeps `ENCRYPTION_KEY`/`DATABASE_URL` out of every compose CLI call (`compose/commands.ts:57-72`). Config-dir hygiene: `/etc/nixploy` 700, `.env` 600, SSH keys/pins/acme/TLS keys 600.

### 2.5 Container / host isolation

Compose safety (`compose/compose-file.ts:519-688`) is a solid deny-list run on raw **and** rendered specs: `privileged`, every namespace key, `security_opt`, `cap_add` (19-entry list), `devices`, `ports`, host-path/`docker.sock`/`type: bind\|tmpfs` volumes, `external`/`name` volumes+networks, `include`/`extends`/`build`/`env_file`, `traefik.*` labels. Traefik uses the file provider only, so container labels are inert. Host bind mounts, host-privileged templates (Portainer/Dozzle/wg-easy), local-socket `docker.*`, `nixploy-server` schedules and host TLS store all require `assertInstanceAdmin`. The gaps are in what the deny-list never reaches (Swarm-level container hardening) and one write path.

### 2.6 SSRF / egress

There is a real central guard, `utils/public-url.ts` (`assertPublicHttpsUrl` :78, `assertSafeOutboundUrl` :108, `assertSafeSmtpHostname` :160, `assertSafeGitCloneUrl` :197): deny-list of loopback/RFC1918/link-local/metadata + DNS pre-resolution, `redirect: "error"` on every `fetch`. Traefik-side SSRF does not exist: backend URLs are always `http://<appName>:<port>` with server-generated names (`modules/traefik/config-writer.ts:240-246`), the middleware union is closed (no `forwardAuth`/`serversTransport`, `:82-87`), reserved names block `nixploy`/`nixploy-postgres` (`utils/validators.ts:10-35`). Webhook payload `clone_url`s are extracted but never fetched. A baseline `member` has almost no panel-side outbound reach (uptime probes, public-only, status code only). Findings are about the admin-gated opt-outs and the guard's shape.

### 2.7 Input handling / shell

All 118 exec call sites were reviewed: **no exploitable shell-injection sink.** Every tenant value is `shellQuote`d or gated by a strict regex/enum; the two unquoted-by-design sites rely on `APP_NAME_RE` (`monitoring/remote.ts:374`) and `REDIS_DATA_DIR_PATTERN` (`backups/runner.ts:532`). ## 3. Hardening roadmap (ordered)

Ordered by (blast radius × ease). Items 1–5 are one-line-to-one-day fixes that close every High; 6–10 are the structural work; the rest is hygiene that keeps the good discipline from eroding.

1. **Gate `compose.update` on `hostPrivileged`** (2.5) — add `assertInstanceAdmin` + reset the flag on any source change; add a tenancy test. *S, closes docker.sock escalation.*
2. **Require instance admin for Swarm joins** (2.3) — at minimum for `swarmRole: "manager"`; default worker; audit `server.setup`. *S.*
3. **Stop shipping `.env` in instance backups** (2.11) — exclude it and/or encrypt the archive; document key custody. *S.*
4. **Body/size caps** (2.1, 2.7) — Traefik `buffering` on the dashboard router, zod `.max()` on big strings, WS `maxPayload`, `watchPaths` caps + memoised globs. *S, removes the cheapest DoS.*
5. **Security headers** (2.1) — `headers()` in `next.config.ts` (CSP `frame-ancestors 'none'`, nosniff, Referrer-Policy, Permissions-Policy) + HSTS middleware in `dashboard.ts`. *S.*
6. **Network segmentation** (2.5/2.10) — `nixploy-internal` overlay for panel↔Postgres; per-service private networks for apps and DBs with Traefik attached per network; DB external ports opt-in. *M, the single biggest posture change.*
7. **Container hardening defaults** (2.5) — `CapabilityDrop ALL`, `no-new-privileges`, `PidsLimit`, log rotation, quota-derived resource limits; validate the `z.unknown()` Swarm overrides. *M.*
8. **API-key scopes + expiry + prefix** (2.2) — honour `permissions` (capability subset, org allowlist), default 90-day expiry, `nxp_` prefix; route the deploy webhook through `buildApiKeyContext`. *M.*
9. **Egress hardening** (2.6) — pin resolved IPs (undici `connect`/`lookup`), instance-admin toggle for private egress per provider, re-validate stored URLs at use, `protocol.allow` env for git, fuller IP range list. *M.*
10. **Key rotation + KDF** (2.4) — `ENCRYPTION_KEYS` fallback list + re-encrypt script, scrypt for passphrases, boot-time refusal of placeholder keys; move build env/args off argv (`--env-file` 0600, BuildKit `--secret`). *M.*
11. **Docker control-center ownership** (2.3) — reuse `ws/access.ts` label resolver in `dockerRouter`; rank-bind infra capabilities in overlays. *M.*
12. **Audit completeness** (2.9) — auth events via better-auth hooks, the 16 un-audited routers, IP/UA columns, retention + org-delete preservation, optional forwarding. *M.*
13. **Supply chain** (2.8) — bump `nodemailer`/MCP SDK, `pnpm audit --audit-level high` in CI, cosign + provenance on GHCR images with updater verification, SHA-pinned actions, checksummed installer, lockfile for `migrate-deps`. *M.*
14. **Auth polish** (2.2) — per-account login bucket, password strength check, setup token, documented admin-recovery path, audit impersonation. *S.*
15. **Long term** — move builds/exec into a socket-holding sidecar so the web process drops root (2.10); AI compose context opt-in and `ai.use` at deployer (2.4); `secrets.read` default review (2.4).
