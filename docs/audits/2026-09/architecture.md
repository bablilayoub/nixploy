# Nixploy — architecture & scalability audit

Branch `work/stability-and-landing` @ `5771d7b`, 2026-09-10. Scope: `packages/server/src`, `apps/web/server.ts`, `apps/web/src/app/api/*`, `docker/`, `install.sh`, `update.sh`. Findings from the stability sweep (`docs/status.md`) are deliberately excluded. Every claim below was read in code; paths are repo-relative, `server/` = `packages/server/src/`.

## 3. Cheap wins (< 1 day each)

1. **Graceful shutdown + crash guard** (#4): SIGTERM handler in `apps/web/server.ts` (close HTTP, `closeWebSocketServer()`, `schedule.gracefulShutdown()`, cancel running jobs and mark rows `error: interrupted`), `process.on("unhandledRejection")`, `--stop-grace-period 90s` in `install.sh`/`update.sh`.
2. **Local build timeout** (#6): pass `remoteCommandTimeoutMs()` into `spawnLocal`, add a job deadline in `processJob`.
3. **Per-app mutex + pending-job coalescing** in `queue.ts` (#1, partial): refuse/replace a second pending job for the same app; serialize same-app jobs even when `NIXPLOY_DEPLOY_CONCURRENCY > 1`.
4. **Log follower by byte offset** (#5): `fs.stat` + `fs.read` from offset; emit chunks from `DeploymentLogger.write` on an in-process emitter; drop the per-client 500 ms DB query.
5. **Index migration** (#9): 8 indexes listed above via `pnpm db:generate`.
6. **Retention** (#10): prune `deployment` rows (keep N per service, 30 d) and `<config>/schedules/*.log`; replace the in-memory `live` set with a SQL anti-join.
7. **Atomic + idempotent Traefik writes** (#11): tmp+rename, hash compare before write.
8. **Real `/api/health`** + HEALTHCHECK target + `--limit-memory` (#12).
9. **Reconciler batching** (#8): one `listServices` + one `listTasks` per pass; group compose probes by server.
10. **Metrics N+1** (#3, partial): batch env→org lookup and alert-rule load once per pass.
11. **Docker listing micro-cache** (#14): 10 s TTL around `docker.containers/images/swarmServices`, `compose.containers`, `getDatabaseStatus`.
12. **`update.sh` pre-upgrade `pg_dump`** to `<config>/backups/pre-update-<version>.sql.gz` + printed restore command (#13).
13. **Release the queue slot before side effects** (#16).

## 4. Structural (> 1 week)

1. **Durable deploy queue** (#1): `queued` status, DB-claimed jobs (`FOR UPDATE SKIP LOCKED`), per-server + per-app concurrency, restart-safe resume of queued jobs, cancel-and-replace on new commits, queue position/ETA in the UI. This is also the prerequisite for a separate worker process.
2. **Split the process** (#4, #12): keep Next+tRPC+WS in `nixploy`, move the deploy worker + crons into a `nixploy-worker` service sharing Postgres and the config volume; crash blast radius shrinks, UI stays up during updates, and the worker can be memory-limited separately. Needs #1 and a small event bus (Postgres `LISTEN/NOTIFY` is enough) for `finish`/status pushes.
3. **Metrics store** (#2, #3): replace JSONL rewrite with append-only files + compaction or a `metric_sample` table with rollups; one `listContainers` per pass; consider the Docker events API instead of polling for status.
4. **Remote-server transport** (#7): SSH connection pool with keepalive and channel multiplexing, per-server circuit breaker, all fan-out crons grouped by server with bounded parallelism; reuse the pool for dockerode-over-SSH and the WS log/terminal streams.
5. **Push instead of poll** (#14, #5): one authenticated `/ws/events` stream (deployment status, service status corrections, queue depth) consumed by TanStack Query invalidation; retire most `refetchInterval`s.
6. **Streaming backups** (#18): pipe dumps to S3 multipart uploads; same for restores.
7. **Upgrade contract** (#13): boot-time schema/version compatibility check, additive-only migration policy with two-release deprecation, and an ops runbook for "schema ahead of image" recovery.
