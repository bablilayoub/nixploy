## What the stability sweep did (2026-09-10/11)

Seven read-only audits (deploy engine, compose/DB/templates, Traefik/domains/previews, auth/tenancy/API, integrations/jobs, ops scripts, web UI ×4 partitions) produced ~120 confirmed findings; six fix passes plus a remote-server redesign landed them. Each commit body on `work/stability-and-landing` lists exactly what changed. Highlights, most important first:

- **Security**: compose files are rendered before validation (the `$VAR` / `~` / `volumes.name:` bypasses gave tenants host root or other tenants' volumes); tenant env never reaches the docker CLI; per-app private networks stop cross-tenant DNS; host uniqueness across orgs (route hijack); WS 2FA gate + Origin check + container-label ownership; instance backups instance-admin only; volume prune guards; update image validation/quoting; reserved app names; invitation binding; per-key rate limits.
- **Broken features made real**: HTTPS on the default certificate (502), stack deploys (rejected by the current CLI), remote servers (Swarm calls now hit the primary, tasks pinned by `node.id`), custom git SSH keys, previews (ports/volumes/port/auth/fork refs), rollbacks (were an empty tab), deploy notifications (never emitted), backup exit status (silent empty dumps) and restores > 96 KB, GitOps diff/apply semantics (TLS downgrade + redeploy-everything), `update.sh` (crashed on every run), database volume orphaning, mongo replicaSet (never started — now rejected), fork-PR previews.
- **UI**: capability gating everywhere (viewers stop seeing controls that 403), error states instead of misleading empty copy, correct invalidations, better-auth `{ error }` handling, setup-wizard retry, status polling after deploy, log viewer reconnect stop, hydration fixes.
- **Landing**: rebuilt (`apps/landing`) and then redesigned to a strict monochrome layout (centered hero + framed dashboard shot, stack marquee, stats, statement, code-to-production accordion, 2×3 features, security, plan cards shared with `/pricing`, two-column FAQ, CTA). Theme tokens in `globals.css` are greys/white only; `components/ui.tsx` holds the shared `Button`/`WindowFrame`/`SectionHeading` primitives.

- **2026-09-18 (any app behind the panel login — v0.4 is complete)** — the last item of the release, and the fourth thing the incumbent's comparison column charges for. A `nixployAuth` middleware on a domain and that host is behind this panel's sign-in: no second identity provider, no sidecar, no per-app user list, and because it *is* the panel's login, the organization's two-factor and required-SSO rules come with it for free. Migration 0039 is one enum value; everything else is new code.

  Three legs. `/api/app-auth/verify` is what Traefik asks on every request (204 allowed, 401 for a non-navigation, 302 to sign in); `/app-auth/authorize` runs on the panel with a real session, evaluates the policy and mints a one-time code; `/_nixploy/callback` runs **on the tenant's own hostname** and turns the code into a cookie. That last one is the whole design: the config writer emits a second Traefik router per protected domain, `Host(<app>) && PathPrefix(/_nixploy/)`, pointing at `nixploy-dashboard` and carrying **no** forwardAuth middleware, so the cookie is host-only — one protected app's session is never sent to another, and the panel's own session cookie never reaches a tenant domain. Both tokens are `<payload>.<hmac>` over `signingKeys()` derived from the `ENCRYPTION_KEYS` chain (first signs, any verifies), domain-separated so a cookie cannot be used as a code, and bound to the host they were issued for. **No session table**: the check is a signature, which is why `verify` on every asset costs nothing — policies are cached ten seconds and `saveMiddlewares` invalidates.

  **Four things bit, all of them worth writing down.** Next treats a folder starting with `_` as *private* and silently does not route it, so the callback lives at `apps/web/src/app/%5Fnixploy/callback` (the documented escape; the public path is unchanged). Traefik's default router priority is the rule's byte length, which ties when the app router also has a path — the callback router carries an explicit 100000 instead. Traefik reaches the panel at `http://nixploy:3000`, which resolves nowhere in a local checkout where the panel runs on the host and the proxy runs in Swarm, so `NIXPLOY_PANEL_INTERNAL_URL` now overrides it (and the same variable feeds the dashboard router's target, so the maintenance middleware works locally for the first time too). And the allow-list needed an axis the plan never named: **teams**. A member scoped to teams whose teams do not reach the project the app lives in is refused — before the explicit user grant — because otherwise the app's own hostname would have been a second door into a project the panel hides.

  Everything fails closed: a missing domain id, an unreadable policy or a forwarded host that does not match the domain row all answer 403 rather than passing the request on. The endpoint is reachable on the panel's public origin as well, which is harmless (it reads headers and a cookie and grants nothing to its own caller) but is exactly why the authorize leg re-checks the host against the real row before redirecting to it — without that it is an open redirect wearing a session.

- **2026-09-18 (teams and project-level access — v0.4 item 7)** — the biggest thing left in v0.4 and the one that touches every tenancy path.
