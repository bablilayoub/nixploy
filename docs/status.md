## What the stability sweep did (2026-09-10/11)

Seven read-only audits (deploy engine, compose/DB/templates, Traefik/domains/previews, auth/tenancy/API, integrations/jobs, ops scripts, web UI ×4 partitions) produced ~120 confirmed findings; six fix passes plus a remote-server redesign landed them. Each commit body on `work/stability-and-landing` lists exactly what changed. Highlights, most important first:

- **Security**: compose files are rendered before validation (the `$VAR` / `~` / `volumes.name:` bypasses gave tenants host root or other tenants' volumes); tenant env never reaches the docker CLI; per-app private networks stop cross-tenant DNS; host uniqueness across orgs (route hijack); WS 2FA gate + Origin check + container-label ownership; instance backups instance-admin only; volume prune guards; update image validation/quoting; reserved app names; invitation binding; per-key rate limits.
- **Broken features made real**: HTTPS on the default certificate (502), stack deploys (rejected by the current CLI), remote servers (Swarm calls now hit the primary, tasks pinned by `node.id`), custom git SSH keys, previews (ports/volumes/port/auth/fork refs), rollbacks (were an empty tab), deploy notifications (never emitted), backup exit status (silent empty dumps) and restores > 96 KB, GitOps diff/apply semantics (TLS downgrade + redeploy-everything), `update.sh` (crashed on every run), database volume orphaning, mongo replicaSet (never started — now rejected), fork-PR previews.
- **UI**: capability gating everywhere (viewers stop seeing controls that 403), error states instead of misleading empty copy, correct invalidations, better-auth `{ error }` handling, setup-wizard retry, status polling after deploy, log viewer reconnect stop, hydration fixes.
- **Landing**: rebuilt (`apps/landing`) and then redesigned to a strict monochrome layout (centered hero + framed dashboard shot, stack marquee, stats, statement, code-to-production accordion, 2×3 features, security, plan cards shared with `/pricing`, two-column FAQ, CTA). Theme tokens in `globals.css` are greys/white only; `components/ui.tsx` holds the shared `Button`/`WindowFrame`/`SectionHeading` primitives.

### UX sprint B — unified service pages (2026-09-11)

Landed in `apps/web` (uncommitted at the time of writing): UX audit F8/F9/F10/F11/F13/F14/F15/F16/F17/F26/F27/F31/F34.

- **One service page frame.** `components/services/service-page-header.tsx` is the single header for application, compose and the five database pages: breadcrumb `Projects / <project> / <environment> / <service>` (all linked, env link is `?env=<name>`), one status badge (the in-flight deployment badge replaces it while a build runs), and an action cluster driven by a `ServiceActions` array — `primary` actions stay visible at every width, the rest collapse into the `sm:hidden` overflow menu. Per-kind hooks (`use-application-actions.ts`, the compose/database mutations) are unchanged; they just build the array.
- **One tab order** for every kind: **General · [Compose file | Connection] · Deploy · Runtime · Domains · Environment · Backups · Advanced · Settings**, each kind rendering only the tabs it has. Advanced (mounts/ports/redirects/security/healthcheck/placement/swarm/rollbacks) is top-level and URL-synced as `?tab=advanced&advanced=<name>`.
- **Deep links survive.** `useSyncedTab` takes an `aliases` map; `SERVICE_TAB_ALIASES` (in the hook) maps the one retired id, `config` → `environment`. Everything else (`?tab=deployments|logs|advanced|backups|environment|…`) still resolves through each page's `SUB_TAB_PARENT` table. **Add a row to `SERVICE_TAB_ALIASES` whenever a service tab id is retired.**
- **Observability IA.** Incidents and the audit log are Monitoring tabs (`/dashboard/monitoring?tab=fleet|incidents|audit`); `settings/incidents` and `settings/activity` are `redirect()` stubs. `IncidentsView` / `ActivityView` / `MonitoringView` take `embedded` to drop their own `PageHeader`. Settings drops the "Observability" group and gains an instance-admin-only "Instance" group holding Platform.
- **Activity tray.** `components/layout/activity-tray.tsx` (bottom-right, in `AuthenticatedLayout`) lists running deployments from the shared query plus locally registered long operations — `useTrackedActivity({ active, … })` for a pending mutation, `trackActivity` / `settleActivity` for fire-and-forget ones. While it is on screen the body carries `data-activity-tray="1"` and `globals.css` lifts the sonner toast stack above it. **There is no org-wide "running backup runs" procedure** (`backup.runs` / `volumeBackup.runs` are per-id), so backups/restores only appear when started from a page that registers them — see the handoff if a server-side `backup.running` is added.
- **Discoverability.** The palette registers a "This Service" group (Logs / Domains / Environment / Terminal / Deploy this service) on any service route, plus Incidents, Audit log and a Documentation row; its cmdk `filter` scores the label above the keywords (a third of the weight), which is what fixed "dom" matching "New Database". Shortcuts: `g l` / `g o` / `g e` on service pages, `g d` Docker, `g p` projects, `g t` templates, `g m` monitoring, `g s` schedules, `g ,` settings — all listed in the `?` overlay together with a docs link. `components/ui/help-link.tsx` (`<HelpLink slug="…">` → `https://nixploy.com/docs/<slug>`; slugs must exist in `apps/landing/src/lib/docs/pages.ts`) is attached to Isolated deployment, Docker Stack vs Compose, Swarm role (×2), Publish mode, Traefik config, Reinstall, Auto updates, host-privileged templates, shared variables, watch paths and Swarm config.
- **Vocabulary.** Deployment `done` reads **Succeeded** everywhere (`status-badge.tsx`, `lib/status.ts#deploymentStatusLabel`, preview deployments, the dashboard list); `error` reads **Failed** in the dashboard list. Dates go through `<DateTime>` / `formatRelative` in deployment history, the update card, the backups lists and the dashboard.
- **Org accent (F34).** `OrgBrandingProvider` sets `--primary` **and** a luminance-derived `--primary-foreground` (a pale accent used to render white-on-white), plus `--brand`, which `UnderlineTabsTrigger` uses for the active-tab underline. `--brand` defaults to `--primary` in `globals.css`, so the panel stays monochrome until an accent is saved.
