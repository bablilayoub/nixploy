# Domains & Traefik

Nixploy routes all inbound HTTP(S) traffic through a single Traefik v3 reverse
proxy. This document covers how routing works, how to expose a service on
localhost and on real internet domains, and how to debug routing problems.

## Architecture

```
internet ─► :80/:443 ─► nixploy-traefik (global swarm service)
                            │  file provider, watches:
                            ▼
              $NIXPLOY_CONFIG_DIR/traefik/dynamic/<appName>.yml
                            │
                            ▼
                  http://<appName>:<port>   (overlay network)
```

- Traefik runs as the global swarm service `nixploy-traefik` (image
  `traefik:v3.5.0`), publishing host ports 80 and 443, attached to the shared
  overlay network (`NIXPLOY_NETWORK`, default `nixploy-network`).
- Static config (`traefik.yml`) is regenerated by `ensureTraefikSetup()`
  (`packages/server/src/modules/traefik/setup.ts`) on app start and whenever
  web-server settings change. It defines entrypoints `web`/`websecure`, the
  file provider, and the `letsencrypt` ACME resolver (HTTP-01 challenge on
  port 80).
- Dynamic config: **one YAML file per app** in the dynamic dir, written by
  `writeAppTraefikConfig()` (`modules/traefik/config-writer.ts`) every time a
  domain/redirect/basic-auth row changes (`resyncServiceTraefik`). Traefik's
  file provider watches the directory and hot-reloads — no restarts.
- With zero domains the file is removed (`removeTraefikConfig`), which also
  happens on service deletion. If you delete things by hand, stale files cause
  502s — delete the orphan YAML.

## Generated YAML anatomy (per domain)

- One **service**: `http://<appName>:<port>` load balancer
  (`passHostHeader: true`). For compose, the target is
  `<appName>-<serviceName>-1`.
- One **router** on entrypoint `web` with rule
  ``Host(`<host>`) && PathPrefix(`<path>`) ``.
- When **HTTPS** is on: the `web` router gets a per-app `redirectScheme`
  middleware (http→https) and a `websecure` router carries TLS —
  `certResolver: letsencrypt`, an inline custom certificate
  (`tls.certificates`), or the default cert for `certificateType: none`.
- `internalPath` becomes an `addPrefix` middleware (public `/public/*` →
  upstream `/internal/*`); redirects and basic auth become named middlewares
  shared by the app's routers.

## Localhost / development domains

Use the **generate** button in the domain dialog: it creates a
`<random>.traefik.me` host. `traefik.me` is a wildcard DNS service that
always resolves to `127.0.0.1`, so the domain works on your machine with no
DNS setup — Traefik just needs the Host header to match.

Requirements for a working route:

1. The service is deployed and its container is running.
2. **Container port is set correctly** — the port the app listens on inside
   the container (e.g. 3000 for Next.js, 5678 for http-echo, 9000 for
   Portainer). An empty port falls back to 80 and is the #1 cause of 502s;
   the UI therefore requires it.
3. Host matches exactly (no scheme, no trailing slash).

Debug a 502 in this order: router exists in the app's YAML → target
host:port in `servers[].url` → container running and listening on that port
(`docker ps`) → service attached to `nixploy-network`.

## Real internet domains

1. Point the domain's **DNS A record** at the server's public IP (AAAA for
   IPv6). Ports 80 and 443 must be reachable from the internet.
2. Set a **Let's Encrypt email** in Settings → Web Server (rewrites the ACME
   section of `traefik.yml`).
3. Add the domain in the service's Domains tab, set the container port,
   enable **HTTPS** and pick certificate **Let's Encrypt**. Traefik solves
   the HTTP-01 challenge on first request and stores certs in `acme.json`.
4. Plain HTTP without a certificate also works (HTTPS off).

Custom certificates: upload cert/key in Settings → Certificates, then choose
**Custom** in the domain dialog; the pair is inlined into the app's dynamic
YAML as `tls.certificates`.

## Preview deployments

Enable **Preview Deployments** on an application's Source tab
(`isPreviewDeploymentsActive`). Provider webhooks then:

- `opened` / `synchronize` / `reopened` → create or redeploy
  `pr-<n>-<appName>.<wildcard>` via `modules/preview`
- `closed` (and merge/fulfilled/rejected equivalents) → tear down the variant

Manual create from the Preview Deployments tab still works without the toggle.


Managed servers join the **primary** Swarm (see `setupServer` in
`modules/cluster/servers.ts`). Traefik remains the cluster-wide global
service on managers. Worker nodes do not get their own Traefik or overlay
init — they schedule user workloads onto `nixploy-network`. Manager remotes
get Traefik config dirs prepared so the global Traefik service can bind-mount
if scheduled there.

Dynamic YAML for services placed on a remote is still written via
`execAsyncRemote` under `/etc/nixploy/traefik` when that server hosts the
file provider mounts.
